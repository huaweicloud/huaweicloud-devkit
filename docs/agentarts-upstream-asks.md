# AgentArts 上游诉求清单

日期: 2026-10-22。依据: agentarts-sdk 0.1.7 钉版源码 + 43 个 CLI fixture + 本仓对抗评审循环 + 2026-10-29 G1 gateway/target 全生命周期会话 + 同日 G2 验证闭环会话（引证见 `docs/agentarts-pr0-findings.md` 陷阱编号与 `docs/agentarts-scenario-plan.md`）。每项标注证据等级与解锁影响。devkit 侧已用 MCP 桥（`src/agentarts-memory.mjs`，工具 `huaweicloud_agentarts_memory_*`）补全数据面可达性——上游修复后 CLI 路径自动流经既有 wrapper 机制，桥降级为冗余纵深。

## S0 待真机裁决（bridge 落地后新增）

- `memory get -o json` 首查是否回传 api_key（`_space_info_to_dict` 无条件含该键，服务端行为未知）——若回传，wrapper 的 readonly get 成为 key 找回路径。
- bridge 工具族真机 e2e（12 方法信封/分页/序列化实测）。【部分裁决 2026-10-27: 8 读 + 4 写全族已在真实 space 上使用（U2-U6 会话），信封/分页/检索/抽取扇出行为实测——剩余: top_k 显式调大时的截断行为; U7 批量 delete_memories 整批 e2e（组合已单测, 待用户批准一次真实批量删除裁决）】
- 检索阈值三分叉（0.3 hook / 0.7 插件 MCP / 0.5 SDK 默认）的召回行为差异。【裁决 2026-10-27: 桥路径（MemorySearchFilter）默认**无过滤**——min_score None 被序列化丢弃（陷阱 29）; **显式 min_score=0.01 实测仍全量返回——服务端过滤整体不生效**（陷阱 31, U6）, 0.5 未单独测但同一代码路径推断相同; 0.3/0.7 常量在实测分数量级（0.000016-0.14）上会滤空一切, 不可移植】
- `add_messages` 抽取管道延迟量级（多快可检索）。
