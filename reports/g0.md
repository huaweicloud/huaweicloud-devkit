## 做了什么

`test/codex-approval-config.test.ts` 三处钉死的计数全部改为从 roster 派生，`plugins/huaweicloud-core/.mcp.json` 不动（17 块已在上游就位，顺序与 roster 一致）。doctor 实现零改动。

1. **两处 real-doctor 正则（原 line 484 / 551）**：提取共享常量 `REAL_DOCTOR_POSTURE_PASS`，用 `new RegExp` 从 `APPROVAL_TOOLS.length` 与 `CODEX_APPROVAL_MODE_ENV` 插值构建。这与既有派生先例一致——doctor 自己的 PASS 行（`src/agents/codex-config.ts:425`）与 row 级单测（原 line 254）都这样派生。
2. **line 47 的长度钉**：`assert.equal(APPROVAL_TOOLS.length, 17, ...)` 没有可派生形式——roster 长度对自身断言是空断言，其防重复名的职责又被紧邻上一行的 `deepEqual(Object.keys(block), [...APPROVAL_TOOLS])` 完全覆盖（roster 有重名时 fromEntries 折叠键、deepEqual 必红）。所以派生的等价形式是**删除**该行。这是本 PR 唯一的判断点，理由如上。

**突变验证**（证明派生 guard 仍抓真缺陷，不是"改断言语义换绿灯"）：临时从 `.mcp.json` 删掉 shutdown 块后跑该测试文件，exit 1，25/26——红的是完全派生的 committed-file guard（"the committed repo .mcp.json carries exactly the roster tools block and the ask env"），零字面量参与。`git checkout` 还原后回到 26/26。
