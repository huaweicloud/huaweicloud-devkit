# 任务：修复 huaweicloud-devkit 插件（基于真实场景测试的缺陷清单）

## 背景

本插件（仓库：`git@github.com:huaweicloud/HuaweiCloud-Devkit.git`，本地路径 `~/.agents/huaweicloud-devkit`）在真实场景"登录华为云 → 购买新加坡 ECS（配置参考已有 Vector-SSY-1 实例）"中完成了全部操作，但暴露若干能力缺口。请按下面清单逐项修复，保持插件现有设计哲学（安全优先、零依赖、read-only 工具 + skills 引导 + 审批闸门）不变。

## 已确认缺陷（按严重度排序）

### P0-1 写操作参数无法学习：`--help` 被策略拦截

- 现象：`huaweicloud_run_readonly_command` 传 `["ECS","CreateServer","--help"]` 返回 "Huawei Cloud write operation blocked..."，连本地帮助都不给看；代理因此无法通过插件获知写操作的确切参数，被迫去查外部 API 文档。
- 位置：`plugins/huaweicloud-core/src/safety-policy.mjs` `classifyHcloudArgs`（约 L135）：应先识别 `--help`、`--version` 等元参数并判为 read-only（帮助命令不产生云端副作用），再做 write 前缀判断。
- 验收：`run_readonly_command ["ECS","CreateServers","--help"]` 能返回帮助文本。

### P0-2 版本检测命令过时

- 现象：`huaweicloud_check_cli` 执行 `hcloud --version`，KooCLI 7.x 返回 `[USE_ERROR]The --version parameter format must be '--param=value'`，却因 exitCode=0 误报 installed=true。
- 位置：`plugins/huaweicloud-core/src/tools.mjs` `runVersionCheck`（约 L110）改执行 `hcloud version`（或 `hcloud --version` 失败时回退 `hcloud version`）。
- 验收：在 KooCLI 7.x 上 `huaweicloud_check_cli` 输出干净版本号。

### P0-3 无操作名发现机制

- 现象：正确操作名与直觉不符：`ListServers`→`ListServersDetails`、`CreateServer`→`CreateServers`、镜像查询在 `IMS GlanceShowImage`（不在 ECS）。全程靠 CLI 报错提示猜名。
- 建议：在 `huaweicloud-capability-discovery` 技能中新增指引："先用 `hcloud <Service> --help` 列出该服务支持的操作，再挑选精确操作名"；或新增只读 MCP 工具 `huaweicloud_list_operations`（service 参数）。
- 验收：给定意图"列出 ECS 实例"，工具/技能能引导出 `ListServersDetails`。

### P0-4 超时挂死：20s 硬超时 + SIGTERM 不生效

- 现象：查询 cn-north-4（89 台实例）时 `run_readonly_command` 60s 无响应。`hcloud-cli.mjs` `runHcloud` 20s 后 `child.kill()`，但 KooCLI 进程未退出，`close` 事件不触发，Promise 永不 resolve。
- 位置：`plugins/huaweicloud-core/src/hcloud-cli.mjs`（timeoutMs 默认 20_000）：① 提高默认超时（如 60s）并在 kill 后加 `SIGKILL` 兜底（`child.kill('SIGKILL')` 或 force kill 计时器）；② 把 `timeoutMs` 暴露到 MCP 工具的 inputSchema（tools.mjs `TOOL_DEFINITIONS`）。
- 验收：大区域查询能返回或被明确超时错误终止，不再无限挂起。

### P1-1 KooCLI 安装与凭证配置零教学

- 现象：check_cli 只说"去安装"；cli-and-auth 技能只说"对话外配置凭证"，用户不知道装什么、配什么、AK/SK 去哪创建。
- 建议：在 `huaweicloud-cli-and-auth/SKILL.md` 补充（引用官方文档即可，不内置二进制）：
  - 安装：`https://support.huaweicloud.com/qs-hcli/hcli_02_003.html`（Linux 官方下载 `https://cn-north-4-hdn-koocli.obs.cn-north-4.myhuaweicloud.com/cli/latest/huaweicloud-cli-linux-amd64.tar.gz`）
  - **安装位置建议**：装到用户目录 `~/.local/bin/hcloud`（无需 sudo，解压即用）；Windows 解压到 `%USERPROFILE%\hcloud` 加入用户 PATH；`~/.local/bin` 需在 opencode/agent 进程的 PATH 中（spawn 靠 PATH 找可执行文件）。建议 `huaweicloud_check_cli` 检测失败时返回上述指引，并支持环境变量（如 `HCLOUD_BIN`）指定 hcloud 路径。
  - 凭证：AK/SK 在控制台"我的凭证→访问密钥"创建；`hcloud configure init`（交互）或 `hcloud configure set --cli-access-key=.. --cli-secret-key=.. --cli-region=..`
  - 字段说明：Access Key ID / Secret Access Key / Region（如 ap-southeast-3）/ Project ID（可自动获取）
- 验收：新手按技能文档可独立完成安装+配置。

### P1-2 区域意图理解缺失

- 现象：用户说"买**新加坡**的ECS，参考一台名字含SSY的实例"，代理却全地域盲扫（含 cn-north-4 等中国区），多发了 6 次无关查询并额外触发超时缺陷。SSY 实例本就在新加坡（ap-southeast-3）。
- 建议：在 `huaweicloud-capability-discovery/SKILL.md` 增加区域语义规则：① 从用户语句提取区域暗示（新加坡→ap-southeast-1/3，香港→ap-southeast-2，北京→cn-north-4 等）；② 目标操作区域优先，参考/对比资源不确定位置时**先询问用户**，禁止全地域盲扫；③ 提示词中给出区域-服务端点的映射查询方式（如 API Explorer 地区和终端节点）。
- 验收：输入"新加坡买 ECS 参考 SSY"，代理只查询新加坡区域或先提问，不扫描中国区。

### P1-2 写操作执行路径缺失

- 现象：插件只规划不执行（README 明示），真实购买只能：用户批准后由代理在 shell 直接执行 `hcloud ECS CreateServers`（绕过插件）或用户手动执行。
- 建议（二选一，需产品决策）：
  - A：新增带审批的写执行工具（如 `huaweicloud_run_approved_command`，仅当用户显式确认的 exact 命令可执行），保留脱敏与审计；
  - B：`huaweicloud_plan_cli_command` 的返回中增加"可复制执行块"，把执行责任显式交给用户，并在技能中说明该边界。
- 验收：写场景下，用户明确知道"谁执行、怎么执行"。

### P1-3 无 KooCLI 语法细节教学

- 现象：KooCLI 数组参数下标从 1 开始（`--server.nics.1.subnet_id`），写 `.0` 报错；参数格式要求 `--param=value`。
- 建议：cli-and-auth 技能补充数组下标与 `=` 格式说明，并给一个 CreateServers 最小示例。
- 验收：代理能一次写出可执行的创建命令（含 dry_run 预检步骤）。

### P1-4 无重试机制

- 现象：`ShowJob` 偶发 `[NETWORK_ERROR]Connection timed out`，需手动重试。
- 建议：`runHcloud` 对网络类错误自动重试 1-2 次（指数退避），并在工具返回中标注重试次数。
- 验收：模拟断网后恢复，命令自动成功。

### P2-1 文档与实现不符

- `huaweicloud_show_profile_redacted`（tools.mjs 约 L127-135）：工具描述/返回文案称"Direct profile inspection is sensitive... blocked"，实际因 `allowCredentialRead:true` 放行并正确脱敏。请统一文案为"已通过脱敏管道返回"。

### P2-2 安全体验：密码类输入提醒

- 本次创建命令含 adminPass，明文出现在 shell 历史。建议在 safety 技能与 plan 工具输出中提示："涉及密码的命令请勿留存于 shell 历史（可 `history -d` 或改用非交互注入）"。

## 修复约束

- 保持零运行时依赖（只用 Node 内置模块）。
- 保持安全模型：AK/SK/密码永不进入对话上下文；写操作必须有显式用户批准。
- 修改后运行 `npm test`（9 个用例）与 `npm run validate`，并补充针对上述修复的新单测。
- 修改 skill 文件后，同步更新本地已安装副本：`~/.config/opencode/skills/` 与 `~/.agents/skills/`。

## 交付

- 每个修复附：变更文件、原因、验证方式。
- 更新 README 中与实现不符的说明。

## 迭代二回归 + 新场景（OBS 静态站部署）补充缺陷

> 迭代二（07af688）已修复 P0-1~~P0-4、P1-1~~P1-4、P2-1、P2-2，回归验证全部通过。以下为回归与新场景发现的新问题，优先级从高到低：

### P0-5（新·安全）obsutil 写命令绕过审批闸门

- 现象：`obs mb`、`obs cp`、`obs rm`、`obs chattri`、`obs mkdir`、`obs sync` 等被安全策略判为 `allow / risk=unknown_read`，可直接经 `huaweicloud_run_readonly_command` 执行，plan 工具也不提示 write。
- 位置：`plugins/huaweicloud-core/src/safety-policy.mjs` `classifyHcloudArgs`/`policy.json`：write 前缀表只覆盖 API 风格动词（Create/Delete/Update...），未覆盖 obsutil 命令词表。KooCLI 的 obs 服务是 obsutil 包装（服务名小写 `obs`，命令为 mb/cp/rm/chattri/mkdir/sync/mv/put 等）。
- 建议：对 service=obs 增加专用命令词表分类：读类（ls/stat/help/cat/sign/version）、写类（mb/cp/rm/mv/chattri/bucketpolicy/lifecycle/mkdir/sync/abort/restore/archive/clear/config/update/share-*），写类走与 API 相同的 deny→审批流。
- 验收：`plan_cli_command ["obs","mb",...]` 返回 risk=write/deny；`run_readonly_command` 执行 obs 写命令被拒绝。

### P1-5（新）`huaweicloud_list_operations` 对 OBS 失效

- 现象：`list_operations OBS` 返回 "No such command: --help"。KooCLI 的 obs 服务是 obsutil 风格：命令格式为 `hcloud obs help`（小写服务名 + `help` 子命令），不是 `hcloud <Service> --help`。
- 建议：list_operations 检测到 `hcloud <svc> --help` 失败时，回退尝试 `hcloud <svc> help`（并处理小写服务名 obs）；或内置已知特例（obs→obsutil）。
- 验收：`list_operations "OBS"` 返回 obsutil 命令列表（ls/stat/cp/mb/...）。

### P1-6（新）obsutil 目录上传语义无教学

- 现象：`hcloud obs cp <本地目录>/ obs://bucket/devkit/ -r` 将本地目录名作为对象前缀（键变成 `devkit/public/...` 而非 `devkit/...`），与常见工具（aws s3 cp）不同；一次部署因此错误上传并返工。
- 建议：cli-and-auth 技能增加 OBS 小节：obsutil 目录上传会以源目录名作为前缀；如需"内容直接落入前缀"，先把本地目录重命名为目标名，或使用 `-dryRun` 先验证键名；建议默认流程先跑 `-dryRun`。
- 验收：技能文档能引导代理第一次就写对上传命令（或先 dryRun 验证）。

### P1-7（新）静态网站托管配置无路径

- 现象：obsutil 命令集无 `website` 命令，无法用 CLI 开启 OBS 静态网站托管（默认首页、自定义域名、CDN 加速）；插件未提示该步骤需控制台或 REST API（PUT /?website）完成。
- 建议：capability-discovery/cli-and-auth 技能对"静态网站部署"场景给出完整路径提示：OBS 上传（CLI 可做）→ 静态托管开关（控制台/API 需要）→ 域名/CDN（可选），避免代理在 CLI 内死磕。
- 验收：意图"部署静态网页到 OBS"，路由结果包含"静态托管开关需控制台/API"的提示。

### P1-8（新）OBS 独立凭证配置教学缺失

- 现象：`hcloud configure` 之后 OBS 仍报 "Please set ak, sk and endpoint in the configuration file!"；OBS 使用独立 `~/.obsutilconfig`，需 `hcloud obs config`（交互式）配置。插件教学未覆盖（该设计属华为云工具本身，但插件应教会代理/用户此步骤）。
- 建议：cli-and-auth 技能补一句：使用 `hcloud obs` 前需 `hcloud obs config`（交互式输入 AK/SK/endpoint，endpoint 如 obs.cn-north-4.myhuaweicloud.com）；配置含凭证，必须在对话外由用户执行。
- 验收：技能文档覆盖该步骤。
