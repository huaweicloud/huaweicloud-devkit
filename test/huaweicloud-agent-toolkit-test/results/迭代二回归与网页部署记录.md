### 1.2 迭代二新增缺陷（回归中发现）

- **G13（安全·严重）**：obsutil 写命令绕过审批闸门。`obs mb`/`obs cp`/`obs rm`/`obs chattri` 等被安全策略判为 `allow / risk=unknown_read`（write 前缀表仅覆盖 Create/Delete/Update 等 API 风格动词，未覆盖 obsutil 命令）。后果：这些写操作可经 `huaweicloud_run_readonly_command` 直接执行，plan 工具也不会提示 write。**修复优先级最高。**

## 第二部分：新场景——部署 huaweicloud-open-capability-home 到华为云

### 2.1 场景与路由

- 仓库：`git@github.com:huaweicloud/huaweicloud-open-capability-home.git`，Vue 3 + Vite 多页静态门户，构建产物 `portal/public/`（275 个文件/25.1MB）
- 路由结论（插件 service_catalog 仅返回通用推荐序，未具体到服务）：静态站 → OBS 静态托管。本地 `npm run build` 产出产物（本地开发动作，非云能力）
- 部署目标（用户指定）：现有桶 `openplatform-prod`（cn-north-4），新建目录 `devkit`

### 2.2 执行流水

1. `huaweicloud_list_operations OBS` → **失败**（见 G15）
2. `obs help` / `obs help cp` 确认命令集（obsutil 风格：mb/cp/chattri/bucketpolicy/rm…，**无 website 命令**）
3. `obs stat openplatform-prod`：standard / cn-north-4 / 76 对象
4. 上传（经 run_approved_command，`-acl=public-read`）→ **发现路径错误**：内容进了 `devkit/public/`（见 G16）
5. 用最小测试目录验证 obsutil 目录语义 → 确认本地文件夹名会成为对象前缀
6. 用户批准修正：删除错误前缀 + 清理测试前缀；本地目录改名 `devkit` 重传到桶根
7. 重传 275 对象成功 → 验证：
   - `https://openplatform-prod.obs.cn-north-4.myhuaweicloud.com/devkit/index.html` → **200 OK**
   - JS/CSS 等子资源 → **200 OK**
8. ⚠️ 静态网站托管（无后缀访问 /devkit/ 显示首页、自定义域名、CDN）需控制台开启，插件无能力也无提示（G17）

### 2.3 部署场景新缺口

| #   | 缺口                        | 现象/影响                                                                                        |
| --- | --------------------------- | ------------------------------------------------------------------------------------------------ |
| G13 | obsutil 写命令绕过审批闸门  | mb/cp/rm/chattri 判为 allow/unknown_read，可经只读工具执行（安全）                               |
| G14 | OBS 需独立凭证配置          | `hcloud obs config`（obsutilconfig），插件教学缺失；凭证本身是华为云工具设计（用户认可）         |
