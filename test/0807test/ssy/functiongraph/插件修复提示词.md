# 任务：修复 huaweicloud-devkit 插件（基于 Function Graph 真实场景测试）

## 背景

huaweicloud-devkit（npm 包 huaweicloud-devkit-test，`npx huaweicloud-devkit-test install`）在真实场景"从零环境创建 Function Graph 定时函数 + APIG HTTP 触发器"中完成了全部操作，但暴露若干能力缺口。请按清单修复，保持插件设计哲学（安全优先、read-only 工具 + skills 引导 + 审批闸门、零依赖）不变。

测试记录：`~/.agents/huaweicloud-agent-toolkit-test-report/devkit-test/FG场景测试记录.md`

## 已确认缺陷（按严重度排序）

### P0-1 search_docs / retrieve_skill 全部失效（路径 bug）

- 现象：`huaweicloud_search_docs` 恒返回 count=0；`huaweicloud_retrieve_skill` 返回 "not found"，且 `Available:` 列表为空。
- 根因：`tools.mjs` 中 `SKILLS_ROOT = <plugins>/skills`（`/home/ssy/.config/opencode/huaweicloud-plugins/skills`），但安装器 `setup-cli.mjs` `installOpenCode()` 把 skills 复制到 `~/.config/opencode/skills`（顶层），两处不一致。
- 建议：统一路径——SKILLS_ROOT 改为 `~/.config/opencode/skills`，或安装器把 skills 装入 `huaweicloud-plugins/skills` 并让 SKILLS_ROOT 与其一致。二者必须一致且测试覆盖。
- 验收：`search_docs("创建函数")` 返回 huawei-functiongraph 等结果；`retrieve_skill("huawei-functiongraph")` 返回完整内容。

### P0-2 执行类操作被误判为 read-only（安全）

- 现象：`FunctionGraph InvokeFunction` 被 `plan_cli_command` 判为 `allow / unknown_read`，可经 `huaweicloud_run_readonly_command` 直接执行——函数调用有真实副作用（执行代码、产生调用、可能触发下游）。
- 建议：分类增加 `execution` 风险类（如 Invoke*、SyncInvoke*、AsyncInvoke* 及 obsutil 写命令词表），execution 类必须走审批（deny→approved_command），不能过只读工具。
- 验收：`plan_cli_command ["FunctionGraph","InvokeFunction",...]` 返回 deny。

### P0-3 zip 代码上传陷阱无预警

- 现象：`CreateFunction --code_type=zip --code_filename=index.zip` 创建"成功"，但**代码未上传**：用不存在的 `nonexistent.zip` 同样成功，两者 code_size/digest 完全一致（占位值）。zip 函数执行空代码（返回 event 回显）；`code_type=inline` 一切正常。
- 建议（两层）：① 技能层：明确"KooCLI zip 上传不可靠/需验证，建议 inline 或先验证 code_size 变化；创建后必须 InvokeFunction 验证返回值"；② 工具层：plan/执行后校验——本地 code_filename 是否存在、创建响应 code_size 是否>占位值、或提供上传后的差异提示。
- 验收：按技能文档走 zip 路径时，代理在创建后能发现"代码未生效"并回退 inline 或修复。

### P1-1 APIG/DEDICATEDGATEWAY 触发器必填参数零教学

- 现象：创建 DEDICATEDGATEWAY 触发器漏 6 个必填参数时只报误导性错误 `FSS.1417 api not register in apigw`；正确参数（instance_id、match_mode、protocol、name、type、env_name）需从 100+ 行 --help 提取；API 名称禁用连字符（regexp 校验失败）也无提示。
- 建议：huawei-functiongraph skill 补充「触发器类型→必填参数表」（TIMER/APIG/DEDICATEDGATEWAY/OBS/SMN 等）+ 命名规则（APIG API 名禁 `-`）+ 错误码映射（FSS.1417 = 缺参数或实例未匹配，先自查 instance_id/match_mode/protocol/type/env_name/name）。
- 验收：按技能文档可一次构造成功创建 DEDICATEDGATEWAY 触发器的命令。

### P1-2 删除类陷阱与跨服务清理无教学

- 现象：① `DeleteFunction` 传 `:latest` URN 报 FSS.0400，需去版本后缀（无提示）；② 删除 FG 的 DEDICATEDGATEWAY 触发器**不级联删除 APIG 上的 API**，产生残留（需手动 `APIG DeleteApiV2`，无提示）。
- 建议：skill 补充：删函数 URN 去 `:latest`；FG 触发器清理后需检查 APIG/对应服务侧残留并清理；错误码映射补 FSS.0400。
- 验收：按技能执行删除流程后无残留。

### P1-3 凭证配置与 CLI 安装零教学

- 现象：`check_cli` 未安装时仅给 URL；凭证仅有"对话外配置"一句。新用户不知道装什么、配什么、AK/SK 去哪获取。
- 建议：cli-and-auth 类技能（或 getting-started）补充：安装步骤（官方 URL/下载/解压/放 `~/.local/bin`/PATH/HCLOUD_BIN）；凭证（控制台「我的凭证→访问密钥」创建 AK/SK、`hcloud configure init` 交互式、字段含义、Region 如 cn-north-4）。
- 验收：新手按文档可独立完成安装+配置。

### P1-4 hcloud 执行器无 cwd 支持

- 现象：`hcloud-cli.mjs` spawn 无 cwd 选项；FG zip 上传等"需 cd 到包目录"的命令无法表达（本次先 cd 再启动 MCP server 规避）。
- 建议：`runHcloud`/工具 inputSchema 暴露 `cwd`（白名单目录或相对当前工作目录）。
- 验收：`run_readonly_command` 支持 cwd 参数。

### P2-1 安装器不处理已有 opencode.jsonc

- 现象：安装器只写 `opencode.json`，忽略已存在的 `opencode.jsonc` → 双配置冲突（两个文件各含一个指向不同位置的 huaweicloud MCP）。
- 建议：安装器优先读写 `opencode.jsonc`（存在时），或合并两个文件后删除冗余。
- 验收：已有 jsonc 的机器安装后仅一份配置。
